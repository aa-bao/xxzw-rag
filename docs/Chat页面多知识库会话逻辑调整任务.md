# Chat 页面多知识库会话逻辑调整任务

## 1. 背景

Chat 页面已经支持一个会话同时绑定多个知识库，但当前前端仍把“已选择的知识库”同时用于：

1. 决定本次对话的检索范围；
2. 过滤左侧历史会话列表。

这会导致用户选择一个或多个知识库后，只能看到与当前选择匹配的部分会话。其他历史会话会暂时消失，容易让用户误以为对话记录丢失。

本任务需要拆分这两个职责：

- 历史会话列表默认展示全部会话；
- 知识库选择只用于确定新会话的检索范围；
- 打开已有会话时，恢复并展示该会话原本绑定的知识库。

## 2. 目标体验

### 2.1 历史会话列表

- Chat 页面加载后，左侧默认展示当前用户的全部历史会话。
- 默认按照会话最后更新时间 `updated_at` 倒序排列，最近更新的会话在最上方。
- 选择知识库不得自动过滤或隐藏历史会话。
- 每条会话继续展示其绑定的知识库名称；多知识库会话可显示前两个名称和总数，例如：`售后规则 / 平台规则 等3个`。
- 如果以后需要按知识库查找历史会话，应增加独立的“历史会话筛选器”，默认值为“全部知识库”。该筛选器不属于本任务的必做范围。

### 2.2 新建对话

- 点击“新对话”后，进入尚未绑定知识库的新会话状态。
- 在主聊天区域中提供一个明确的知识库多选区域，用于选择本次新对话使用的一个或多个知识库。
- 至少选择一个知识库后才允许发送第一条消息。
- 用户发送第一条消息时创建正式会话，并将所选 `kb_ids` 绑定到该会话。
- 如果当前后端接口要求提前创建会话，也可以在知识库选择完成后创建，但不得因为选择知识库而过滤历史列表。
- 未选择知识库时，发送按钮应禁用或给出“请先选择知识库”的明确提示。

### 2.3 打开已有对话

- 点击历史会话后加载该会话的完整消息记录。
- 同时从该会话的 `kb_ids` 恢复当前会话的知识库标签/展示状态。
- 已有会话的知识库集合视为会话属性，不允许在原会话中直接修改。
- 如果用户希望更换知识库，应新建对话，而不是修改已有会话的 `kb_ids`。
- 切换已有会话不得清空或隐藏左侧其他历史会话。

### 2.4 当前会话信息

- 主聊天区域顶部应明确展示当前会话正在使用的知识库。
- 单知识库显示名称；多知识库以标签或紧凑列表展示。
- 新对话尚未完成选择时，显示“请选择本次对话使用的知识库”。
- 已有会话的知识库展示应为只读。

## 3. 推荐状态拆分

不要继续使用同一个状态同时控制“历史列表过滤”和“当前会话知识库”。建议至少拆分为：

- `conversations`：当前用户的全部历史会话；
- `activeConversationId`：当前打开的已有会话 ID，或新对话状态；
- `activeConversationKbIds`：已有会话绑定的只读知识库集合；
- `newConversationKbIds`：新对话创建前用户选择的知识库集合；
- 可选的 `historyKbFilter`：未来用于筛选历史列表，默认不启用或为“全部”。

不要再通过 `selectedKbIds` 直接计算默认历史会话列表。若保留该变量，应明确它只代表新会话选择，不能参与 `filteredConversations`。

## 4. 推荐交互流程

```text
进入 Chat 页面
  -> 加载知识库列表
  -> 加载全部历史会话
  -> 按 updated_at 从新到旧展示
  -> 默认可打开最近会话，或停留在空状态

点击已有会话
  -> 加载该会话消息
  -> 恢复该会话 kb_ids
  -> 只读展示其知识库

点击“新对话”
  -> 清空当前消息区域
  -> 进入新对话状态
  -> 展示知识库多选区域
  -> 选择至少一个知识库
  -> 发送第一条问题
  -> 创建并绑定会话
  -> 将新会话插入历史列表顶部
```

## 6. 兼容性约束

- 保留现有多知识库会话能力和 `kb_ids` 数据结构。
- 保留会话重命名、删除、引用按钮、引用抽屉和流式回答能力。
- 不得重新引入用户消息因 Motion key 冲突而透明消失的问题。
- 所有带 `v-motion` 的循环节点必须保持互不冲突的 key 命名空间。
- 切换会话期间继续使用竞态令牌或等效机制，避免较晚返回的历史请求覆盖当前会话。
- 不得修改已有会话的知识库归属。
- 不得因为某个知识库被取消选择而删除或隐藏历史消息。
- 现有工作区可能存在其他任务改动；提交前必须确认只暂存本任务文件和本任务对应的代码块。

## 7. 必须补充的测试

至少覆盖以下场景：

1. **默认展示全部会话**
   - 模拟不同 `kb_ids` 的多个历史会话；
   - 页面加载后全部可见；
   - 按 `updated_at` 倒序排列。

2. **选择新对话知识库不影响历史列表**
   - 点击“新对话”；
   - 选择一个或多个知识库；
   - 左侧全部历史会话仍然可见。

3. **新对话必须选择知识库**
   - 未选择知识库时不能发送；
   - 选择至少一个后可以发送；
   - 创建接口收到正确的 `kb_ids`。

4. **已有会话恢复绑定知识库**
   - 点击一个多知识库会话；
   - 页面展示该会话的全部知识库；
   - 知识库选择为只读或不存在可编辑入口。

5. **切换会话不影响完整历史列表**
   - 在不同知识库会话之间切换；
   - 会话列表数量和项目保持不变。

6. **新会话进入列表顶部**
   - 完成第一条消息并创建会话后；
   - 新会话出现在历史列表顶部；
   - 其他历史会话仍然存在。

7. **现有 Chat 功能无回归**
   - 第二条用户消息在流式回答完成后仍可见；
   - 引用数字按钮仍可点击；
   - 切换会话时过期请求不会覆盖当前消息。

## 8. 验收标准

- 打开 Chat 页面即可看到全部历史会话，无需先选择知识库。
- 全部历史会话按最后更新时间从新到旧排列。
- 点击“新对话”后，用户能在主区域选择多个知识库。
- 未选择知识库时无法发送第一条消息。
- 新会话创建后绑定所选知识库，并进入历史列表顶部。
- 打开已有会话能恢复其原有知识库集合，且不可直接修改。
- 选择新对话知识库、切换已有会话均不会导致其他历史会话消失。
- 会话重命名、删除、流式回答、消息显示和引用按钮功能正常。
- 前端完整测试通过。
- `npm run build` 通过。
- `git diff --check` 通过。
- 提交中不包含无关工作区改动。

## 10. 非目标

本任务暂不包含：

- 修改已有会话绑定的知识库；
- 让每一条问题单独选择知识库；
- 新增复杂的历史会话搜索或筛选系统；
- 修改 RAG 检索、召回、切片或引用算法；
- 重构无关页面或后端模块。
