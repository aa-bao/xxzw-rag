# 有界混合召回与 FAQ 语义切块设计

## 目标

解决 FAQ 的问题与答案被切到不同知识块后，原文问题仍无法进入 `top_k` 的问题，同时避免相邻块扩展把 5 个命中无界放大为 15 个上下文块。

成功标准：

- `1、问题？答：答案……` 作为一个完整语义块入库；单个问答超过上游 500 字限制时，后续片段重复问题前缀。
- 精确或高度重合的中文问题能通过轻量词法信号进入向量候选的前列。
- cosine 相似度仍是阈值判断和 UI 展示值，混合排序分数不冒充相似度。
- 仅全局前 2 个核心命中扩展同文档 `index - 1`、`index + 1`。
- 最终 Prompt 上下文去重后最多 8 块且不超过约 2,000 tokens。
- 多知识库、用户隔离、引用持久化和 SSE 引用保持兼容。

## 方案比较

### 方案 A：只增大 overlap 或 top_k

实现简单，但不能保证完整 FAQ 问答；增大 `top_k` 会把无关块直接送入 Prompt。拒绝。

### 方案 B：命中结果全部扩展相邻块

能够补回断裂上下文，但 5 个核心命中最坏扩张到 15 块，且没有 token 上限。拒绝。

### 方案 C：FAQ 语义切块＋候选池混合重排＋有界邻居扩展

在入库阶段修复语义边界，在召回阶段用低成本词法信号弥补纯向量遗漏，并只对最可信的两个全局核心命中补邻居。采用本方案。

## 数据流

1. 文档解析后的纯文本进入 `split_text`。
2. 切块器先识别 `FAQ` 区域中的编号问答项，再对剩余文本使用现有“段落 > 行 > 句子”切分。
3. 每个最终 embedding 片段写入 Chroma 时保存 `chunk_index` 元数据；旧索引仍可从 `doc:index:hash` ID 回退解析。
4. 查询每个知识库时，Chroma 先取 `max(top_k * 4, 20)` 个向量候选。
5. 候选先按 cosine 阈值过滤，再计算轻量词法分：
   - Unicode NFKC、转小写、移除空白与标点；
   - 规范化查询是正文子串时，词法分为 `1.0`；
   - 否则用中文/字母数字二元字符集合的 Dice 系数；
   - `rank_score = 0.75 * cosine + 0.25 * lexical`。
6. 每库返回自己的前 `top_k` 核心结果；多库按 `rank_score` 稳定合并，再整体截断为全局 `top_k`。
7. 全局前 2 个核心结果作为种子，读取同一知识库、同一文档的前后相邻索引。相邻块重新计算真实 query cosine，但不受命中阈值限制，因为它们是结构上下文而不是独立命中。
8. 按“种子窗口优先、剩余核心结果随后”的顺序去重并装箱；达到 8 块或约 2,000 tokens 即停止。
9. 最终上下文进入 Prompt；核心块和实际加入 Prompt 的邻居均写入 Reference，并在 SSE 中返回。`score` 始终是真实 cosine；新增 `is_neighbor` 只标识来源，不改变分数含义。

## 组件边界

### FAQ 切块

`rag-service/src/ingestion/splitter.py` 负责识别 FAQ 问答项。识别仅在出现 `FAQ` 标记的尾部启用，避免把正文普通编号条款误判为问答。问答项必须同时包含编号问题、问号和 `答：`。

完整问答不超过 500 字时保持为一个块。超过 500 字时按答案句子切成多个不超过 500 字的块，每个块都重复问题文本，以保证任一子块可独立检索。

### 混合排序

新建 `rag-service/src/retrieval/ranking.py`，只负责文本规范化、词法分和混合分计算。`RetrievedChunk.score` 保持 cosine；新增 `rank_score` 供排序，默认回退到 `score`，因此测试替身和旧调用方不必立即提供混合分。

### 邻居上下文

`RetrievalModule` 新增默认 `expand_context`，默认实现只执行核心结果的块数/token 装箱，确保非 Chroma 测试替身兼容。`ChromaRetrieval` 覆盖该方法，按 `kb_id + doc_id + chunk_index` 获取邻居并计算真实 cosine。

邻居扩展发生在 `retrieve_multi` 完成全局截断之后，保证多知识库场景仍只有全局前 2 个种子，而不是每库各扩展 2 个。

## 兼容性与迁移

- API 的 `score` 字段继续表示 cosine，相似度阈值语义不变。
- Reference 新增的 `is_neighbor` 先只在运行时/SSE 传递，不新增数据库列；历史消息中的引用缺省为 `false`。
- 旧 collection 没有 `chunk_index` 元数据时解析现有 chunk ID；完整获得 FAQ 切块效果仍必须对知识库执行重建。
- 不新增外部依赖或搜索服务。
- 不改变现有 `top_k`、阈值数据库字段和多知识库“首库配置”规则。

## 错误与降级

- 候选池查询失败：保持现有行为，返回空结果并触发 `empty_response`。
- 词法评分异常：该候选的词法分按 `0` 处理，仍可按 cosine 排序。
- 邻居读取或向量计算失败：记录 warning，使用原核心结果继续回答，不使查询失败。
- token 计算器不可用：回退为中文约 2 token/字、ASCII 约 1 token/4 字符的估算。

## 测试策略

- 切块单测：当前第 23/24 块样例应生成包含完整第一问答的单块；普通编号条款不误判；超长 FAQ 重复问题前缀。
- 排序单测：精确问题位于长块尾部时，词法重排可把向量第 10 候选提升到 top 5；阈值仍按 cosine，不按混合分。
- 多库单测：按 `rank_score` 合并、总 top_k 不变。
- 邻居单测：仅前 2 种子扩展；相邻命中去重；跨文档/跨知识库不串块；8 块和 2,000-token 两个上限均生效。
- QueryEngine 单测：Prompt 使用扩展上下文，Reference/SSE 包含实际采用的邻居并保留真实 cosine。
- 真实回归：问题“半托管商家承责的纠纷范围发生了哪些变化？”重建后应召回包含完整答案的 FAQ 块；若核心块已完整，则邻居扩展不得造成无意义膨胀。

## 非目标

- 本次不引入 Elasticsearch、BM25 服务或 cross-encoder reranker。
- 本次不调整前端知识库配置 UI。
- 本次不自动重建所有知识库；实现验证后由管理员显式触发目标知识库重建。
