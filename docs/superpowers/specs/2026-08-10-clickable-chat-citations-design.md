# 可点击聊天引用设计

## 目标

让聊天回答正文中的资料编号成为可点击引用，例如 `[1]` 和 `[1][2]`。点击编号后复用现有资料来源抽屉，并定位到对应资料。同时兼容当前模型可能生成的 `[1#`、`[1##2#` 等错误标记，避免继续向用户展示残缺语法。

## 范围

- 新回答应使用标准引用格式 `[n]`，多个来源连续写为 `[1][2]`。
- 已有回答中的已知错误格式在展示时规范化：
  - `[1#` 显示为 `[1]`
  - `[1##2#` 显示为 `[1][2]`
- 只有存在于当前消息 `references` 数组中的编号才可点击。
- 编号从 1 开始，与资料来源数组的展示顺序一致。
- 不改数据库中的历史回答原文；兼容处理只发生在展示层。

## 方案

### 后端输出约束

扩展聊天系统提示词，明确要求模型：

1. 事实引用使用 `[n]`。
2. 同一句对应多个来源时使用 `[1][2]`。
3. `n` 必须来自提供给模型的 `untrusted-source id`。
4. 不得生成 `#`、脚注定义或不存在的编号。

该约束降低新回答继续产生错误标记的概率，但前端仍执行校验，因为模型输出不能被视为严格结构化数据。

### 前端解析与渲染

在 Markdown 渲染阶段增加一个小型引用解析模块，而不是在最终 HTML 上做全局正则替换。解析器只处理 Markdown 的普通文本 token，因此不会修改：

- 围栏代码块
- 行内代码
- Markdown 链接及其地址
- 原始 HTML（当前 Markdown 配置本身已禁用 HTML）

解析器识别标准格式和两种已知错误格式，将有效编号渲染为带 `data-reference-index` 的按钮。按钮文本统一显示 `[n]`，并具有可识别的无障碍标签。超出引用数组范围、零、负数或无法完整解析的标记保持普通文本，不制造错误链接。

消息正文容器通过事件委托处理按钮点击，根据当前消息和编号调用现有的 `openRefs`，打开资料来源抽屉并定位到对应条目。这样无需为 `v-html` 生成的每个按钮单独挂载 Vue 组件。

流式回答期间，后端尚未发送 `references` 事件，因此引用先作为普通文本显示；回答完成并收到引用数组后，消息重新渲染为按钮。这避免在资料未到达时产生不可验证的链接。

### 安全与失败行为

- 引用按钮 HTML 只由本地渲染器根据整数编号生成，不拼接模型提供的任意属性或 HTML。
- 点击处理仅接受整数且再次检查数组边界。
- 无有效资料来源时，所有引用标记保持普通文本。
- 错误格式规范化只覆盖明确的数字模式，不改写普通方括号文本。

## 测试

前端单元测试覆盖：

- 单个标准引用 `[1]`
- 连续引用 `[1][2]`
- 错误格式 `[1#` 和 `[1##2#`
- 越界编号和没有资料来源的情况
- 行内代码、代码块和 Markdown 链接不被转换
- 点击有效按钮打开抽屉并定位到正确来源

后端测试覆盖系统提示词包含引用格式约束，以及来源编号仍从 1 开始并与返回引用顺序一致。

最后运行前端测试与构建、后端相关测试，确认类型检查和现有聊天流程没有回归。

## 非目标

- 不修改检索、重排或上下文扩展逻辑。
- 不迁移或重写数据库中的历史消息。
- 不引入新的引用抽屉或新的资料详情接口。
- 不尝试修复除上述已知模式以外的任意模型乱码。
