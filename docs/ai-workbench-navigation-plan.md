# AI 工作台导航改造计划

## 1. 改造目标

将当前扁平的 RAG 知识库导航改造成可扩展的 AI 工作台导航。现有业务能力不重写，先完成产品外壳、信息架构、路由归属和权限展示的调整，为后续 AI 功能提供稳定接入点。

本次改造完成后：

- 产品品牌显示为“AI 工作台”。
- “RAG 知识库”成为一级模块。
- “知识库”“对话”“映射模板”成为 RAG 模块的二级入口。
- “系统管理”成为独立一级模块，包含“设置”“用户管理”，仅账户管理员可见。
- 登录后默认进入“RAG 知识库 → 知识库”。
- 具体知识库详情内的“文档”“检索测试”“配置”继续作为局部导航存在。
- 后续新增 AI 功能时，通过模块注册接入，不在布局中继续堆叠条件判断。

## 2. 信息架构

```text
AI 工作台
├─ RAG 知识库
│  ├─ 知识库
│  │  └─ 具体知识库
│  │     ├─ 文档
│  │     ├─ 检索测试
│  │     └─ 配置
│  ├─ 对话
│  └─ 映射模板（管理员）
└─ 系统管理（管理员）
   ├─ 设置
   └─ 用户管理
```

说明：映射模板用于结构化文档入库，业务上归属 RAG，但保持现有管理员权限。

## 3. 导航交互

### 3.1 一级模块

- 一级项负责表达功能域，不直接与页面项混在同一视觉层级。
- 点击一级项时展开其二级菜单；如果该模块尚未展开，同时导航到其默认二级入口。
- 当前路由所属的一级模块保持展开，并显示模块级激活状态。
- 首版允许同时只展开一个一级模块，降低侧栏噪声。
- 用户主动展开状态保存在前端会话中；路由变化始终具有更高优先级，确保当前页面可见。

### 3.2 二级入口

- 二级项显示页面级选中状态，并使用 `aria-current="page"`。
- 一级展开按钮提供 `aria-expanded`，全部导航支持键盘访问和明确焦点状态。
- 无权限的入口不渲染；直接访问仍由路由守卫拦截，不能只依赖菜单隐藏。

### 3.3 局部导航

- `KbDetailLayout` 内的“文档 / 检索测试 / 配置”保持不变。
- 进入任意知识库详情路由时，全局导航仍选中“知识库”，而不是出现无选中项。
- 全局导航解决“在哪个功能模块”，局部导航解决“在当前知识库做什么”，两者职责分离。

## 4. 路由方案

采用语义化的新地址作为正式地址，同时保留旧地址重定向，避免书签和已有跳转失效。

| 页面 | 正式地址 | 旧地址兼容 |
|---|---|---|
| 知识库列表 | `/rag/knowledge-bases` | `/kb` 重定向 |
| 知识库详情 | `/rag/knowledge-bases/:id/...` | `/kb/:id/...` 重定向并保留参数 |
| 对话 | `/rag/chat` | `/chat` 重定向 |
| 映射模板 | `/rag/mapping-templates` | `/settings/mapping-templates` 重定向 |
| 平台设置 | `/admin/settings` | `/settings` 重定向 |
| 用户管理 | `/admin/users` | `/settings/users` 重定向 |

执行原则：

- 保留现有 route name，优先降低页面内部改动范围；正式跳转统一改用命名路由。
- 根路由 `/`、登录成功、已登录用户访问登录页、404 和无权访问时，统一跳转 `kb-list`。
- 旧地址仅负责兼容，不复制页面定义，避免两套 meta 与权限规则漂移。
- `/api/kb`、`/api/chat` 等后端接口地址不属于前端页面路由，本次完全不改。

## 5. 前端模块设计

### 5.1 导航注册表

新增一个工作台导航模块，例如 `web/src/navigation/workbench.ts`，对布局暴露一个小接口：

```ts
getVisibleWorkbenchModules(userRole, currentRoute): WorkbenchModule[]
```

每个一级模块声明：

- 稳定 `id`
- 中文标题和图标
- 默认子路由
- 可见角色
- 二级入口列表
- 用于匹配模块和入口的 route name 集合

布局只负责渲染返回结果及处理展开状态，不再知道 RAG、管理员或未来 AI 功能的业务细节。权限过滤、父级激活和默认入口选择集中在该模块内测试。

### 5.2 路由元数据

在路由 meta 中增加稳定归属信息：

```ts
meta: {
  workbenchModule: 'rag',
  workbenchEntry: 'knowledge-bases'
}
```

知识库详情的所有嵌套路由均归属 `rag / knowledge-bases`。这解决当前 `route.name === name` 无法在详情页保持全局菜单选中的问题。

### 5.3 布局职责

`AppLayout.vue` 调整为工作台外壳：

- 品牌区显示“AI 工作台”。
- 渲染一级模块和二级入口。
- 保留用户信息和退出能力。
- 不承载具体功能业务状态。
- 继续沿用现有视觉令牌与整体玻璃质感，本次不重做页面视觉世界。

## 6. 实施阶段

### 阶段一：建立导航与路由基础

1. 定义导航类型和模块注册表。
2. 为现有路由补充模块归属 meta。
3. 增加正式路由和旧地址重定向。
4. 将页面内硬编码路径改为命名路由，特别是登录、知识库创建后跳转、删除后返回和详情返回。

交付结果：路由结构已经具备工作台语义，但页面能力保持原样。

### 阶段二：改造工作台侧栏

1. 将扁平 `navItems` 替换为两级模块导航。
2. 实现权限过滤、展开状态、父级/子级激活状态。
3. 更新品牌文案和导航无障碍属性。
4. 保持现有用户区域和退出流程。

交付结果：普通用户只看到 RAG 模块；管理员额外看到系统管理及 RAG 下的映射模板。

### 阶段三：测试与回归

1. 为导航注册表添加单元测试。
2. 为路由默认跳转、旧地址兼容和角色守卫添加测试。
3. 为布局添加普通用户、管理员、详情路由激活态和展开行为测试。
4. 运行前端完整测试、类型检查和生产构建。
5. 在桌面宽度进行一次视觉检查，确认长用户名、两个模块展开、详情页和无权限跳转状态。

## 8. 验收标准

- 普通用户登录后进入知识库列表，只能看到“RAG 知识库”及有权访问的二级入口。
- 管理员能看到“RAG 知识库”和“系统管理”，并访问对应二级页面。
- 任意知识库详情页面都保持“RAG 知识库 → 知识库”激活。
- 刷新任意正式地址后，菜单展开和激活状态正确。
- 所有旧页面地址能无损跳转到正式地址，动态 `id` 和 `docId` 不丢失。
- 无权限用户即使手动输入管理员地址也会被守卫送回知识库列表。
- 新增一个模拟 AI 模块只需要注册模块和路由，不需要修改侧栏渲染逻辑。
- 前端测试、类型检查和生产构建全部通过。

## 9. 本次不做

- 不新增工作台概览首页。
- 不新增第二个 AI 功能或占位菜单。
- 不改后端接口、数据模型和用户空间隔离方式。
- 不重构现有 RAG 页面内部业务逻辑。
- 不在本次引入动态插件、远程菜单或数据库驱动的菜单配置；有真实的第二种实现需求后再建立该 seam。
- 不全面重做视觉品牌；本次只调整工作台外壳与导航层级。

## 10. 风险与控制

- **硬编码旧路径遗漏**：集中搜索 `/kb`、`/chat`、`/settings`，页面跳转改为命名路由，并用旧地址测试兜底。
- **权限隐藏与路由权限不一致**：导航注册表使用与路由守卫一致的角色语义，分别测试“不可见”和“不可直接访问”。
- **详情页父级不激活**：不再根据 route name 相等判断，改用路由 meta 的模块与入口归属。
- **提前抽象过度**：模块注册表只覆盖现有两类一级模块；暂不引入运行时插件接口。等第二个 AI 功能出现后，再根据真实差异深化模块 interface。
