# 检索质量排障：原句查不到（Chroma 距离空间错配）

> 日期：2026-08-07
> 关联：豆包 `doubao-embedding-vision-251215` 替换硅基 `bge-large-zh-v1.5` 后的检索问题

## 一、现象

上传"全球速卖通半托管基础规则.md"后，用文件里的原句提问：

> 如果我对纠纷结果不认可该如何申诉？

系统回复"未找到相关信息"。而实际上答案就在库里（"答：POP店铺，登录交易-退款&纠纷-搜索对应半托管纠纷订单进行申诉，纠纷判责后您有1次7天的申诉机会。"），相似度却被算成 **-0.038**，被 0.20 的相似度阈值过滤掉了。

## 二、根因：Chroma 集合距离空间错配

三层原因，层层递进：

| 层面 | 问题 |
|---|---|
| **根源** | `kb_1_v1` 集合由旧代码创建，创建时未带 `hnsw:space` metadata，Chroma **默认使用 L2 欧氏距离** |
| **中间** | 代码 `_to_chunks` 按**余弦距离**假设换算分数：`score = 1 - distance`（`src/retrieval/chroma.py`） |
| **表象** | L2 距离约 1.03 被算成 `1 - 1.03 = -0.03`，相关文档全被 0.2 阈值过滤 → "找不到" |

### 关键坑：`get_or_create_collection` 的 metadata 只在创建时生效

Chroma 的 `get_or_create_collection(name, metadata={"hnsw:space": "cosine"})` 只在**集合创建时**应用 metadata；集合已存在时，再传 metadata **不会修改已有集合**。因此即使代码中一直写着 cosine 配置，旧集合永远停留在 L2——这就是"代码看着对、实际用的是 L2"的原因。

## 三、排查证据链

1. **库里确认有答案 chunk**（"POP店铺…申诉"），但 Chroma 查询分数为 -0.038
2. **手动对向量算余弦**：用豆包 API 对问句和答案句计算余弦相似度 = **+0.487**（明显相关），与 Chroma 返回的分数完全对不上
3. **直读 sqlite 配置**：`chroma.sqlite3` 的 `collections` 表 `config_json_str` 中 `"space": "l2"` 实锤
4. **手动 L2 排序对照**：对所有库向量按 L2 距离排序，与 Chroma 返回的顺序**完全一致** → 确认 L2 假设成立

## 四、解决方法

1. **备份**旧数据：`cp -r data/chroma data/chroma_bak_l2_<时间戳>`
2. **删除** `kb_1_v1` 集合（Chroma **不允许动态修改距离函数**，只能删了重建）
3. **重建**为 cosine 空间集合：`get_or_create_collection(name, metadata={"hnsw:space": "cosine"})`
4. **重新入库**：将文档重置为 `pending` 并新建 ingest job，worker 重新向量化写入
5. **验证**：原句查询返回答案 chunk，score=**0.4834**，5 条相关结果全部通过阈值；相关单元测试（11 个）全过

## 五、经验教训

### 1. 换 embedding 模型后，除了维度还要检查距离空间

这次豆包向量是**单位向量**（norm≈1.0），L2 与 cosine 排序几乎等价，所以召回顺序没出大问题——真正错的是**分数换算和阈值判断**。如果换成非归一化模型，L2 下的排序本身就会错，后果更严重（召回内容不对，不只是过滤问题）。

### 2. Chroma 集合空间在创建时一次性固定

后续代码改 metadata 不会作用于已有集合；老数据迁移只能删库重建。排查时优先确认集合实际配置（读 sqlite 或 `collection.metadata`），不要只看代码。

### 3. 排查"检索质量"问题的正确姿势

先**手动对向量算相似度**验证模型本身（问句 vs 库中答案），再核对存储层的距离语义。两边分数对不上就能快速定位——本次正是靠"手动算 +0.487 vs Chroma 返回 -0.038"的差异锁定根因。

### 4. 换模型的完整检查清单

- [ ] 模型是否已开通（方舟控制台"开通管理"）
- [ ] 调用端点与输入/响应格式（多模态模型用 `/embeddings/multimodal`，单条输入、dict 响应）
- [ ] 向量维度与 Chroma 集合一致（豆包 vision 支持 `dimensions` 参数固定）
- [ ] Chroma 集合距离空间（`hnsw:space`）与分数换算一致
- [ ] 阈值合理性（豆包相似度分布整体偏高，不相关句子约 0.24，阈值 0.2 偏低）
